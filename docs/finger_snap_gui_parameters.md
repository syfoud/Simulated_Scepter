# GUI 弹指一挥参数说明

这些参数位于设置界面的“进阶设置”页签中的“弹指一挥”区域，独立保存在 `settings.json` 的
`finger_snap_model` 节点中。点击“保存弹指一挥设置”后写入配置；已经运行中的弹指任务不会重建模型，新值从下一次启动弹指任务起生效。

## 2. MC 采样参数

### 控制采样量

控制采样用于学习“当前动作之后应该怎样继续走”，对应 $\varepsilon$-greedy rollout 预算。

- 调大：更容易覆盖稀有状态，均分策略和胜率策略的下游行为通常更稳定。
- 代价：运行时间近似线性增加。
- 它不是最终候选胜率的分母；最终显示来自新的独立评价样本。
- 当存在需要补采的一层后继状态时，预算会在根状态和后继状态之间分配。

配置值不是绝对硬上限。为保证根动作都有样本，实际控制量至少为：

$$\max(control\_rollouts,\ min\_visits\times|\mathcal A|)$$

后继状态也有按合法动作数计算的最低预算，所以日志中的实际控制数可能略高于输入值。

增加采样量不会修复漏节点、错边或感染识别错误。

### 独立评价量

独立评价量用于在冻结下游策略后公平比较当前所有候选动作。每个候选获得等量新样本。

生产调用总是带当前位面目标，因此预算还会在两套评价之间分配：

- 一部分评价最大平均 CD 的下游策略；
- 一部分评价最大目标胜率的下游策略。

存在后继校准时，评价预算还会分配给训练实际访问的深层状态，先改进其策略，再评价直接后继和根动作。因此单个候选的样本数通常小于输入总量，实际总数也可能因“每动作至少一次”和整除取整而略有差异。策略改进样本不会混入最终展示的胜率分母。

- 调大：均分、胜率和候选排序的抽样误差下降。
- 代价：运行时间近似线性增加；其中一部分用于已访问状态的策略改进，但不能替代控制阶段对新状态的探索。
- 稀有成功事件需要更大的评价量。真实胜率若约为 $p$，观察到一次成功通常需要 $O(1/p)$ 量级样本。

### 单动作最低样本

该值有两个作用：

1. 保证当前根动作在控制阶段至少获得指定数量级的强制覆盖；
2. 均分动作不足 `min(2, min_visits)` 次观测时保留规则先验，避免单次异常样本接管策略；深层胜率样本不受根动作最低访问量限制，已发现的成功轨迹会参与学习并接受独立续采验证。

调大会抬高实际最低控制预算；超过 2 后不会再提高深层动作采用均分样本的门槛。它不直接决定独立评价中每个候选的样本数。

### 初始探索率与最终探索率

探索率表示控制采样时随机选择下游动作的概率，取值会自动限制到 $[0,1]$。

- `epsilon_start`：一批控制采样开始时的探索概率。
- `epsilon_end`：该批结束时的探索概率。
- 两者之间按 rollout 序号线性变化。

较高探索率会覆盖更多当前贪心策略以外的分支，也会让更多控制样本用于非贪心动作；较低探索率会更集中地复用当前策略，也更容易保留早期误判。当前默认值为 `0.35 → 0.03`。

当 `epsilon_start >= epsilon_end` 时，探索概率随批次下降；两者都设为 0 代表控制阶段完全贪心。

### MC 随机种子

种子控制模型内部 rollout 的伪随机序列，用于复现和对比调参结果。

- 相同地图、状态、参数和调用顺序通常产生相同模拟结果。
- 识图结果、候选顺序、已执行批次数或实际游戏随机状态变化后，结果仍可能不同。
- 修改种子不会提高理论精度，只是换一组样本；判断稳定性时可以用多个种子交叉验证。

模型不会用这个种子控制游戏中的真实骰子。

## 3. 路径节点补正

五个补正只在“路径选择”阶段使用：

$$排序分=MC均分+节点类型补正$$

它们不改变：

- 实际 CD；
- 展示的 MC 均分；
- 胜率的成功次数和分母；
- 效果动作和慈怀目标的评分。

默认值实现以下微弱偏好：

```text
奖励(0.0005) > 事件(0.0004) > 交易(0.0003)
> 冒险(0.0002) > 虫群事件(0.0001) > 其他(0)
```

`reward2` 使用奖励补正，`trade2` 使用交易补正。战斗、精英、虫群战斗、首领、等待等未列类型补正为 0。

由于一次移动的实际 CD 差通常是整数，当前万分位补正主要处理同分或极接近结果。若把补正设为 `0.5`、`1` 等大值，它会从平局偏好变成能够覆盖实际 CD 差异的目标函数组成部分；负数则表达对相应节点类型的回避偏好。

## 4. 决策依据

### MC-EV

选择独立评价后平均最终 CD 最高的动作。目标 CD 仍会用于显示候选胜率，但不参与当前动作的主排序。

### MC-WR

只要独立评价中至少一个候选观察到成功，就选择胜率最高的动作；胜率相同时比较均分和路径补正。若所有候选胜率均为 0，退化为 MC-EV。

这里的“全为 0”只表示有限样本内没有成功，不能证明数学不可达。

### MC-WR→DP

有非零胜率样本时与 MC-WR 相同；所有候选胜率均为 0 时，改用乐观极限 DP 的当前动作。

DP 回退不表示这条路线出现概率高。

### DP

不运行 MC 推荐，直接选择最有利随机结果下最大最终 CD 的见证轨迹当前动作。

它会把未来环境随机看成总能出现有利结果，因此不能拿 DP 数值当平均 CD 或胜率。

## 5. 目标 CD

三个目标分别应用于当前位面的累计 CD：

$$win=\mathbf1[D_{final}\ge T_k]$$

它们会影响：

- MC-WR 和 MC-WR→DP 的胜率策略；
- 所有 MC 模式显示的候选胜率；
- 对应模式启用 DP 早停时的可达性判断。

它们不会影响：

- MC-EV 的均分定义；
- 地图规则和实际 CD 结算；
- DP 所求的最大 CD 本身。

目标修改后必须重新评价；旧目标下的胜率不能沿用到新目标。

## 6. 第一位面策略阈值

该参数是生产代理在第一位面上的额外保守规则，默认 `0.0` 表示关闭。

当满足以下全部条件时生效：

- 当前是第一位面；
- 模式为 MC-EV、MC-WR 或 MC-WR→DP；
- 模型推荐的不是 `keep`；
- 推荐动作的 MC 均分与 `keep` 均分之差不大于该阈值。

此时生产代理把动作改成 `keep`，避免为了极小的估计优势消耗作弊或重投资源。

例如阈值为 `0.05`：推荐动作均分 82.03、keep 均分 82.00 时会 keep；差值 0.08 时仍执行推荐动作。

注意：该规则比较的是**均分**，即使当前模式按胜率选中了非 keep 动作，也可能被阈值覆盖。DP 模式不使用该阈值。若只希望模型原样执行，保持 0.0。

## 7. DP 早停开关

界面提供三项独立开关，以免与铁血战士早停设置混淆：

| 开关 | 适用模式 |
|---|---|
| DP 模式：理论上限不达标时早停 | DP |
| 胜率模式：同时使用 DP 上限早停 | MC-WR、MC-WR→DP |
| 纯 MC 模式：同时使用 DP 上限早停 | MC-EV |

启用后，系统计算当前确定状态的乐观 DP 上限。若：

$$D_{DP}<T_k$$

则在当前识图和规则模型内连最有利随机轨迹都无法达标，可以结束本轮。等号表示仍存在恰好达标的理论轨迹，不能早停。

MC 模式启用早停不代表正常决策会改用 DP：上限达标时仍按原 MC 模式选择；只有 `MC-WR→DP` 的全零规则会主动用 DP 动作。

早停还受生产环境已有的“允许提前结束”总条件约束。关闭该总条件时，即使计算了 DP 上限，也不会在非主界面盲目按 Esc；系统只会按各界面的正常收尾流程退出到主界面。

## 8. 输入校验与常见误区

- 三个采样整数最小归一化为 1。
- 探索率自动截断到 `[0,1]`。
- GUI 要求采样量、种子和目标 CD 能解析为整数，其余数值能解析为浮点数。
- 路径补正和第一位面阈值没有自动限制；极端值会真实改变行为。
- 10 万控制加 10 万评价通常约比 1 万加 1 万慢一个数量级，这是线性采样成本，不是空间爆炸。
- 目标设得很高而胜率全零时，先区分“有限样本未遇到”与“DP 上限也不可达”。
- MC 随机种子只控制模拟，不会让游戏 reroll 固定。
