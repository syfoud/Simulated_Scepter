# 脚本编辑与定时计划

主窗口的一键长草页提供“脚本编辑器”和“定时计划”入口，两种模式均可使用。它们复用动态发现的内核与 JSON 脚本，不修改调试模式配置。

主窗口“运行脚本”和定时计划会将所选脚本装入所选内核，再通过该内核的 `start()` 运行完整流程。业务内核保留自己的寻路、战斗和状态推进；通用内核运行纯 JSON 动作循环。编辑器中的调试按下面定义的单轮范围执行。

## 编辑动作脚本

脚本编辑器可新建、打开、保存和另存为脚本。项目内脚本默认位于 `actions/`，各模块自带脚本位于 `core/<模块>/actions/`，也可以打开其他位置的 JSON 文件。保存后主窗口立即刷新脚本选项，并选中保存的脚本。

“动作与参数”页按事件展示触发条件及命中后执行的动作。事件可以添加、复制、删除和上下移动；动作可以添加、删除和排序。参数表逐项编辑名称和值，值使用 JSON 格式，例如 `"奖励"`、`[960, 540]`、`true`。文本触发需要 `text` 与 `box`；图片触发使用 `photo`；纯状态触发使用 `state_only`，可配合 `condition`。

“JSON 源码”页编辑完整脚本。切换页面前会校验当前内容；无效输入保留在原页面并显示原因。未识别的扩展字段会保留。内核方法动作以字符串保存，例如 `"select_event"`，它必须由执行脚本的内核提供，编辑器的结构校验不替代内核能力检查。

“校验”和保存会检查事件结构、坐标、时间参数及 JSON 格式；写入采用临时文件替换，失败不会截断原脚本。切换文件或关闭编辑器时，未保存的修改会提示保存、放弃或取消。编辑和保存均不会执行脚本。

### 从游戏画面选取触发标志

先选择编辑器底部的内核，再点击触发条件上方的“从游戏画面选择文字”或“从游戏画面框选图片”。取样使用所选内核的游戏截图和识别接口，处理完毕后释放运行资源，显示冻结的截图供选择。游戏须已启动，并满足内核要求的窗口尺寸。截图前会请求切换到游戏，确认游戏持续处于前台并留出重绘时间；截图期间丢失焦点会丢弃该画面并重新等待。未能在等待期限内获得焦点时提示重试，可点击游戏窗口帮助完成切换，等待期间也可以停止。

取样窗口默认占所在屏幕的大部分可用空间，游戏画面按比例显示，窗口仍可手动调整大小。

文字取样会标出 OCR 识别框，并在右侧列出检测到的文字。点击图中的框或列表项，确认匹配文字后自动填入 `text` 和 `box`。匹配文字可以编辑，按运行时的规则清除数字、英文字母及标点；处理后为空的文字不能作为标志。

图片取样可在截图上拖动框选，支持反向拖动。图片名称优先采用当前事件名，没有事件名时使用“图片标志”；默认目录是 `resource/imgs/script_markers/`，默认同名文件通过编号区分。可以修改图片名称，输入其他保存目录或点击“选择目录”。保存格式为 PNG，省略扩展名时自动补齐，手动选择已有文件时会确认是否覆盖。

确认后填入 `photo`、局部匹配中心 `pos` 和阈值。图像目录内的标志保存相对于图像目录的路径，其他位置保存绝对路径；同名图片按完整路径区分，覆盖后运行时会加载新内容。保存使用临时文件替换，失败不会截断原图。图片与脚本共同构成运行资源，移动项目时需要一起保留，外部图片位置变化时也需修改脚本中的路径。

选取新标志会替换当前事件的文字、图片或纯状态检测字段，保留状态条件、一次触发、间隔以及自定义字段。取消选取不会改变触发条件；取样后仍需保存脚本。

### 在编辑器中调试

调试直接使用当前编辑内容的独立快照，无需先保存，也适用于 JSON 源码页。范围可以选择“当前事件”或“整个脚本”；源码页的当前事件沿用可视化页所选的事件序号。

每次取样或调试使用新建的内核实例，状态条件按该实例当前状态判断，不沿用其他运行任务的状态。

- **按触发条件调试：** 获取当前游戏画面并执行一轮内核触发判断，按事件顺序执行首个命中事件的动作，然后结束；没有命中时仅显示结果。
- **直接执行动作：** 忽略触发器、状态条件及重复限制，按所选范围的事件和动作顺序执行一次。此模式不会为了检查触发器而截图或进行 OCR；动作自身仍会使用其所需的识别接口。

调试会实际操作游戏，执行状态及错误显示在编辑器和主窗口日志中。“停止调试 / 截图”会取消本编辑器尚未启动的队列项，或请求停止本编辑器正在运行的任务，不会停止其他手动任务。主窗口停止按钮及配置的停止热键同样有效。关闭编辑器时会先取消或停止本编辑器的操作，待线程退出后再处理未保存的修改。

两种调试模式都会先请求切换到游戏，确认游戏持续获得焦点后才启动键鼠操作；等待期间可停止。未获得焦点时不会提交动作，并提示切换到游戏后重试。调试等待已提交的键鼠动作实际完成后才报告完成并释放资源；主动停止则清除未执行的动作。

截图取样和调试均进入现有任务队列，遵守当前计划的中断选项；任务线程退出前不会并行启动另一个任务。取样或调试期间暂停编辑，以保证反馈对应提交的事件和参数。

## 配置定时计划

新建计划后填写名称、内核、脚本、执行时间及重复方式，点击“保存计划”生效。列表可以选择已有计划进行修改，也可启用、停用或删除。切换计划或关闭窗口时，未保存的配置会提示保存、放弃或取消。内核选项来自当前可运行模块；计划保存稳定的模块 ID，项目内脚本保存相对路径，外部脚本保存绝对路径。

支持指定日期执行一次、每天同一时间及每周同一时间重复，采用本机时间。每周计划按执行日期的星期几、时分秒重复，例如选择周一 08:00 后，每周一 08:00 执行。保存或重新启用已过期的重复计划时，会直接推进到下一次对应时间。计划保存在 `config/config/schedules.json`，重新打开程序后恢复。

计划仅在程序运行时触发，最小计时检查间隔为一秒。到点已有任务运行或停止中时，计划等待任务线程退出，随后依次启动。手动运行任务也进入同一队列，按计划的到期时间和手动任务的提交时间排序。手动队列仅保留在当前程序运行期间，不跨重启保存。计划不改变主窗口当前选择，手动任务和定时任务使用同一个运行入口与停止按钮。

每个计划提供“允许因其他任务准备执行而强制停止”，默认不勾选；已有计划缺少此字段时也按关闭处理。开关控制当前运行的计划是否可被中断，后续计划自己的开关不决定它能否中断别人。保存后当前运行计划也按更新后的开关处理。

开关关闭时，其他到期计划和手动任务依次等待。开关打开时，其他有效计划到期或手动任务提交后，会对当前计划请求停止，并等待它的线程完全退出后再启动下一项；停止请求只发送一次，停止期间不并行执行新任务。手动启动的任务保持排队规则，计划不会自动中断它们。被中断的一次计划不会恢复，每天及每周计划仍保留下一次执行时间。同一重复计划的下一轮到期不作为“其他任务”中断自身。

程序关闭期间错过的计划不补跑：一次计划停用，每天及每周计划推进至未来的下一次对应时间，保持原时分秒及每周计划的星期几。程序再次启动时不会集中执行过期计划。触发前先保存执行记录，避免同一次计划在重启后重复启动。

内核被移除、脚本不存在或结构错误时，列表记录启动失败；其他有效计划继续运行。每天及每周计划在下一个执行时间继续尝试，一次计划需修改时间后重新启用。计划文件损坏或写入失败时停止计时并显示原因，需要修复存储问题并重新启动程序。列表中的“已触发”表示已发起任务，任务执行结果仍见主窗口运行日志。
