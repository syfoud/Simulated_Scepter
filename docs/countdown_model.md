# 弹指倒计时评估模型

本文是当前生产实现的统一数学说明。规则与接口以
`tool/countdown_evaluator.py`、`tool/countdown_dp.py` 和 `finger_snap.py` 为准。
测试 GUI 与生产环境共用同一套评估后端；旧的典型图 W 表、三地图联合资源分配、
DP 热启动 MC 等方案均不属于当前在线链路。

## 1. 求解边界

游戏包含三个位面，倒计时、作弊次数和重投次数会由实际游戏画面逐位面继承，但模型在任意时刻只装入并分析**当前位面的当前剩余地图**：

$$
\text{画面事实}\longrightarrow\text{当前位面模型}\longrightarrow\text{本次效果、目标或路径建议}
$$

模型不会加载尚未出现的后续地图，也不会用固定“典型图”预留资源。因此它不会预知未来，代价是当前位面的局部最优决策未必是整轮三个位面的全局最优决策。

当前默认累计目标倒计时为：

| 位面 | 目标 CD |
|---|---:|
| 第一位面 | 15 |
| 第二位面 | 75 |
| 第三位面 | 80 |

目标 CD 用于胜率评价、胜率策略和可选的 DP 早停，不会改变 `MC-EV` 的平均 CD 定义。

## 2. 地图、状态与决策阶段

当前地图表示为只向右连接的有向无环图：

$$G=(V,E)$$

节点由识图程序给出，边由几何建图程序生成。节点横坐标按 30 像素容差聚成列。移动到目标节点后，该节点所在列及其左侧所有列都会销毁。

完整事实状态为：

$$s=(n,I,d,c,r)$$

| 符号 | 含义 |
|---|---|
| $n$ | 当前节点 |
| $I$ | 当前传染节点集合，以位掩码保存 |
| $d$ | 当前实际倒计时 |
| $c$ | 剩余作弊次数 |
| $r$ | 剩余重投次数 |

一次决策只处于下列一个阶段：

| 阶段 | 已知事实 | 合法动作 |
|---|---|---|
| 效果阶段 | 本次随机效果已经出现在画面中 | `keep`、`cheat→效果`、`reroll` |
| 慈怀目标阶段 | 最终效果已经确定为慈怀 | 选择一个可传染节点 |
| 路径阶段 | 本步最终效果及随机结算均已确定 | 选择当前节点的一个后继 |
| 终止阶段 | 当前地图没有后继 | 无 |

这一区分非常重要：投骰子时，重投后的新效果尚未确定；寻路时，本步效果已经确定并已反映在状态中。生产代理不会自行伪造随机结果，而是在下一张画面重新读取效果、感染状态、资源和 CD。

## 3. 六种效果与状态转移

环境中的六种效果等概率出现。MC 按真实随机分布采样；DP 则把随机结果视为最有利结果，用来计算理论上限。

| 编号 | 游戏名称 | 模型含义 |
|---:|---|---|
| 1 | 浇灌 | 每个仍活跃的传染源，从其可用相邻节点中随机感染一个；各传染源分别抽取 |
| 2 | 为善 | 当前 CD 增加当前活跃传染节点数 |
| 3 | 对症 | 选择路径后，感染目标节点的可用相邻节点 |
| 4 | 慈怀 | 先选择一个未传染、未销毁节点感染，再选择路径 |
| 5 | 归心 | 从未传染、未销毁节点中均匀随机感染一个 |
| 6 | 可憎 | 不改变感染集合或 CD |

设从当前节点看仍未销毁的节点掩码为 $F(n)$。活跃传染数为：

$$A(s)=|I\cap F(n)|$$

为善的效果增量为 $A(s)$。浇灌只让当前仍活跃的传染源传播；已经销毁列上的历史感染位不会继续传播。

选择路径节点 $j\in succ(n)$ 后，先按移动前的感染集合判分：

$$
\Delta_{move}(j)=
\begin{cases}
+1,&j\in I'\\
-3,&j\notin I'
\end{cases}
$$

随后销毁目标列及其左侧列：

$$I''=I'\cap F(j)$$

因此统一转移顺序是：

```text
观察效果 → keep/cheat/reroll → 随机效果真实结算
→ 慈怀选点（若需要）→ 选择路径 → 移动判分 → 销毁列
```

对症依赖所选路径，所以延迟到移动时应用；其他效果在路径决策前结算。

## 4. 动作与资源

观察到效果 $e$ 后，效果动作集合为：

$$
\mathcal A_e(s)=\{keep\}
\cup\{cheat(k):k\ne e,c>0\}
\cup\{reroll:r>0\}
$$

- `keep`：采用已观察到的效果，不消耗资源。
- `cheat(k)`：消耗一次作弊，把本步最终效果改成 $k$。
- `reroll`：先消耗一次重投，再由游戏产生一个新的随机效果，随后重新进入效果决策阶段。

重复重投没有被几何分布或期望公式压缩。每次重投后的效果和剩余资源都会形成新的实际状态，策略可再次选择 keep、cheat 或 reroll。

## 5. 蒙特卡洛控制与独立评价

### 5.1 两套目标函数

生产后端同时维护两套策略口径。

平均 CD 策略最大化：

$$J_{EV}(s,a)=\mathbb E[D_{final}\mid s,a,\pi_{EV}]$$

目标胜率策略最大化：

$$J_{WR}(s,a)=P(D_{final}\ge T_k\mid s,a,\pi_{WR})$$

其中 $T_k$ 是当前位面的目标 CD。均分最优与胜率最优可能不同：高方差动作可能均分更高但达标率更低，反之亦然。

### 5.2 状态动作价值

MC 的均分 Q 值记录“从本次决策以后获得的 CD 增量”，而不是把过去已经取得的 CD 重复算入：

$$Q(s,a)=\mathbb E[D_{final}-d_{decision}]$$

由于 CD 对未来回报线性可加，均分状态键可以省略当前绝对 CD；胜率依赖距离目标还有多少，因此胜率策略的状态键必须保留当前绝对 CD。

每个访问过的状态动作只保存 `count / total / total_sq` 等在线统计量，不保存全部样本，也不枚举所有感染掩码。

已结算的普通效果不再区分路径状态，只有尚待移动结算的对症需要保留。效果动作按“实际采用的效果＋支付资源后的状态”共享统计；剩余作弊足够覆盖全部后续步骤时，六种骰面共享同一效果选择策略，但执行时仍区分免费保留与消耗作弊。

### 5.3 控制采样

从当前精确状态开始执行完整 rollout。根动作轮流强制覆盖，下游动作采用随批次线性退火的 $\varepsilon$-greedy 策略：

$$
\varepsilon_i=\varepsilon_{start}+
\frac{i}{N-1}(\varepsilon_{end}-\varepsilon_{start})
$$

均分动作未满 `min(2, min_visits)` 次观测时使用基于规则的成长—收割启发式；胜率学习保留已经采到的成功轨迹，不再因深层访问不足 64 次而忽略。控制样本只负责发现和改进策略，不直接充当最终候选报告。

模型对直接后继分配控制预算，并记录训练实际访问的更深决策状态。在评价预算内，优先覆盖常访问状态，按下游到上游顺序以完整 MC 续跑改进策略，覆盖效果、慈怀选点和路径阶段。小批试采胜率持平时保留已有成功策略，避免偶然高分引起不必要切换；随后冻结策略，以新样本评价当前候选。这里不枚举所有状态、不用 Bellman 递推，也不调用 DP。

### 5.4 冻结策略独立评价

完成控制采样后冻结下游策略，对每个当前候选动作分配相同数量的新 rollout：

$$
\widehat\mu_a=\frac1N\sum_{i=1}^{N}D_{a,i},\qquad
\widehat p_a=\frac1N\sum_{i=1}^{N}\mathbf1[D_{a,i}\ge T_k]
$$

同一评价轮次中的候选动作从相同随机状态出发，以共同随机数降低比较噪声。平均策略和胜率策略分别评价，避免用最大均分的下游行为错误代替最大胜率行为。

展示的胜率严格是“该候选最终 CD 达标的实际模拟次数 ÷ 该候选独立模拟次数”，不是启发式分数，也不是 DP 可达性。

### 5.5 路径偏好补正

路径动作可附加极小的排序补正：

$$score(a)=\widehat\mu_a+b(type(a))$$

默认顺序为：

```text
奖励 > 事件 > 交易 > 冒险 > 虫群事件 > 其他
```

补正只用于路径动作的排序，不改变实际 CD、胜率和界面显示的均分。当前默认最大补正为 `0.0008`，设计目的只是在统计结果近似相同或实际 CD 同分时稳定打破平局；设置过大则会覆盖真实收益差异。

## 6. 乐观极限 DP

`ExactCountdownDP` 求解的是：从当前**确定上下文**出发，如果今后所有环境随机结果都取模型允许的最有利值，能够达到的最大最终 CD。

它不是随机过程的期望，也不是胜率：

$$D_{DP}(s)=\max_{\text{合法路径、动作、随机结果}}D_{final}$$

入口阶段的语义如下：

- 效果阶段：当前画面效果已经确定；可 keep，或消耗当前可用资源 cheat/reroll。若 reroll，DP 令重投结果取最有利效果。
- 慈怀目标阶段：效果已确定，只优化合法感染目标和之后的路径。
- 路径阶段：效果与随机结算已经确定，只优化当前路径及未来最有利轨迹，不会重复应用本步效果。

未来每一步的自然随机效果也取最有利结果，所以在构造理论上限时，归心被慈怀支配、可憎被其他有效效果支配。DP 使用拓扑前向展开、感染集合 Pareto 支配剪枝和投影后的浇灌组合来保持精确；超过状态或浇灌组合安全上限时会明确报错，而不是静默近似。

DP 返回最大实际 CD 和一条达到该值的合法见证轨迹。路径微补正参与同 CD 轨迹的选择，但返回的 `max_countdown` 仍是未加补正的真实 CD。

因此：

- `DP` 模式是在追求一条理想情况下的最佳道路；它不能表示该道路实际发生的概率。
- 若 DP 上限仍低于当前位面目标，则在地图识别和规则模型正确的前提下，MC 胜率必为 0，可以安全用于早停。
- DP 上限达到目标只表示“存在一种有利随机轨迹”，不表示胜率高，更不表示必定达标。

## 7. 四种生产决策模式

| GUI 名称 | 当前动作的选择规则 | 是否混用另一求解器 |
|---|---|---|
| `MC-EV` | 选择独立评价平均最终 CD 最高的动作 | 默认不使用 DP；开启对应 DP 早停后只额外计算上限 |
| `MC-WR` | 只要存在非零胜率样本，选择胜率最高者；全为 0 时选择 MC 均分最高者 | 默认不使用 DP；开启对应 DP 早停后只额外计算上限 |
| `MC-WR→DP` | 存在非零胜率样本时同 `MC-WR`；所有候选胜率均为 0 时采用 DP 动作 | 按条件显式切换到 DP |
| `DP` | 直接采用乐观极限 DP 见证轨迹的当前动作 | 不运行 MC 推荐 |

同胜率时先比较候选均分加路径微补正；再相同才使用确定性的动作顺序打破平局。

可选 DP 早停与决策模式彼此独立。MC 模式开启早停后会额外计算 DP 上限，但只要上限仍能达到目标，正常动作仍由所选 MC 模式决定。

## 8. 生产事实同步

后端只给出建议，不把点击视为游戏已经接受。生产代理遵循以下边界：

1. OCR 读取实际效果和资源；
2. 模型给出效果动作；
3. 自动化程序点击；
4. 新画面确认阶段变化后，再同步已发生的资源或感染事实；
5. 路径界面重新识图后，从已确定状态推荐路径；
6. 移动完成后，以实际新画面进入下一步。

识图漏节点、错边、起点误判或感染颜色误判会让求解器正确地优化一张错误地图。提高 MC 样本量无法修复输入模型错误。

## 9. 复杂度与误差

设控制预算为 $N_c$，独立评价预算为 $N_e$，平均一次 rollout 包含 $L$ 个决策，平均活跃传染源数为 $S$：

$$T_{MC}=O((N_c+N_e)LS)$$

MC 空间与实际访问到的状态动作数成正比，每个条目为常数大小。十万级预算仍然需要近似十万级真实模拟，时间通常近似线性增长。

若本批实际访问了 $U$ 个不同决策状态，续采调度额外需要 $O(U)$ 临时空间及 $O(U\log U)$ 排序时间；策略改进的 rollout 仍计入评价预算，临时状态记录在本次推荐结束前清空。

DP 的实际成本取决于每个拓扑节点保留下来的非支配感染集合数及浇灌投影组合数，最坏情况仍可能呈指数增长；状态和组合安全上限用于防止无界运行，并不把 DP 变成近似算法。

有限 MC 样本存在以下统计限制：

- 候选差值小于采样标准误时，排序可能翻转；
- 所有候选显示 0 胜率只说明本批未观察到成功，不等价于数学不可达；
- 候选越多、样本越少，最高显示均值越容易有轻微赢家偏差；
- 共同随机数能降低比较方差，但不同动作消耗随机数的方式不同，不能完全消除噪声。
